# 私人卡池（阶段二）

用户已确认流程并授权实现、测试后发布。以 2.9.0.0 交付，图片识别属于阶段三，当前无模型调用。

入口：卡池中心 → 我的卡池 / 新建私人卡池 → 系列资料 → 多图上传 → 网格或手动框选 → 批量校对 → 仅保存 / 保存并继续入库。未知归属可存草稿；发布必须填写组合、成员、版本。单人和娃卡可以用本人或产品名作组名，不强制 CP 配对。数量默认0，目录保存不写个人库存。

## 模块
- `src/private-pools.mjs`：纯校验、固定编号投影；卡面编号含卡池范围，名称修改不重建。
- `src/api.ts`：`private-pools` 仅本人目录，`private-pools/save` 草稿与发布快照分离、版本冲突保护、请求重放；`private-pools/upload` 媒体请求幂等；`private-media/:id` 每次读取校验 owner，包括管理员自己的私人内容。
- `migrations/0005_private_pools.sql`：新增私人目录和媒体归属表；系列唯一索引防同账号并发重复创建。不修改旧账户payload和公共目录。
- `public/private-pool.*`：IndexedDB按账号保存本机草稿及待上传字节、裁切任务和原请求；云端草稿手动保存。原图不改写；Canvas只从原图裁切。每张原图上限2.25MB、30张原图、500卡面、每组100卡面。
- `GET /api/catalog`：公共目录加当前账号已发布私人目录；`/api/library` 仍只含公共。卡池中心与详情使用catalog；文字模型仍只使用公共目录，不发送私人图片。
- 原有 `pool-center-core` / `inventory` / `cost-math`：多组合数量、成本、批次、整批校验、保存凭据及安全重试全部复用。私人/公共同名目录不自动合并。

## 边界与恢复
发布后不得删除卡面或更换归属组编号；可新增版本、调整图片和组显示名称。历史批次及成本不随目录修改重算。真正关联私人/公共卡池、AI识别、投稿审核不在本阶段。
私人媒体仅通过本人授权路由读取，禁止分享进公共库。原图库个人替换功能未改；私人目录更新图片优先使用当前目录图，个人独立替换仍只作用本人。
生产D1备份包含私人目录、发布快照、原图与裁切图；原有网页库存JSON备份仅涵盖库存与被引用图片，不含尚未入库的私人目录和原图。当前未新增跨账号目录备份导入功能，不能将库存JSON当作完整私人目录恢复包。
失败保留输入与原请求；裁切中断通过任务队列续传，不重复生成。保存冲突可“返回修改（保留填写）”，重新核对版本后保存。
回退2.8.0.0时保留新增数据库表及数据；旧版不提供私人目录/媒体入口。若已产生私人库存，应优先向前修复，必要回退期间暂停私人卡池操作，不能还原旧数据库删除新采购。
