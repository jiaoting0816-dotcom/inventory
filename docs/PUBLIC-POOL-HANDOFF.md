# 公共卡池交接 — 2.3.0

## 范围与项目地图
- `src/library.mjs`：共享卡图的公开字段投影、图片槽位；不包含私人库存或金额。
- `src/pool-registry.mjs`：已有 377 组卡款的固定池/CP/版本编号登记。只能增补，不能按显示名称重新生成已有编号。
- `src/pool-identity.mjs`：CP 别名及固定编号解析。新增别名先检查是否与其他角色冲突。
- `public/pool-intake.js`：公共分类 → 卡池 → CP、数量框；详情中的旧批次成员分配和历史。
- `src/inventory.mjs`：入库、防重复请求、同款追加；原销售 FIFO 逻辑。
- `src/member-allocation.mjs`：只拆分未售部分，保持数量、剩余成本及自留属性。
- `src/api.ts`：登录、账号作用域、共享目录查找、版本冲突重试；客户端不能自行传入可信 `_asset`。
- `src/backup.mjs`：备份格式校验；保留入库请求编号。
- `src/gifts.mjs` / `src/stock-adjust.mjs`：赠品、库存调整。本轮未改。
- `tests/public-pool.test.mjs`：本轮回归用例。其他业务按对应测试模块读取。

## 业务规则
1. 公共卡池没有个人数量、成本、销售；每次写入只更新登录账号。
2. `shared_id` 是卡款固定编号；`pool_id`、`cp_id`、`variant_id` 随新入库保存。改私人名称不会新建同款。
3. DT/DewTee、SK/SeaKeen 等别名在入库及共享卡图匹配时归一；共享目录原图片 URL 槽位不重排。
4. 同账号同 `shared_id` 追加批次；旧款无编号时按分类、系列和 CP 别名匹配。多个候选或成员配置不符时拒绝自动合并，提示从详情处理。
5. 新增入库请求编号防止网络重试重复增加库存。批量入库整体校验后保存。
6. 旧库存不自动迁移。用户在详情选择批次、配置成员，分配总数必须等于该批次剩余数量。按整数分摊成本，余数由累计分摊吸收。
7. 保留已售/赠品来源批次，撤销销售与赠品退回仍返回原批次；其返回数量可再次分配。完全未使用的源批次拆完后删除空壳，完整原内容存在手动分配历史中。
8. 空图片合法；不编造图片或成本。没有成员配置的普通物品使用单个数量框。
9. 不自动抓取外部图片，不重写原账户配置、图片、成本、自留和赠品。
