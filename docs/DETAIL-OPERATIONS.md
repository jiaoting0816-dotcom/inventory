# 库存详情操作中心：已确认需求（2026-11-22）

状态：v2.7.0 已部署（da41c00 / 52080c19）；84项测试、隔离API及代理执行的桌面/手机页面验证通过。用户验收待完成。后续版本执行 `docs/RELEASE-POLICY.md`。

## 用户确认范围
详情内完成整对CP、团体成员或单一卡面版本的新增入库、盘点调整、自留、转赠品、批次查看、更正和成本补录/修改。自动带入归属，不跳到其他页面，不多层弹窗。桌面使用40–48px缩略图、紧凑行和短输入框；手机自然换行。常用入库/调整按钮直接可见，其余详情内可达。

## 当前证据与复用点
- `src/inventory.mjs` 的 intake 分支统一建立 batches、saved_at、intake_request_key、intake_receipts。需逐一确认卡池、快速录入、批量导入调用链，不能将记录缺失直接认定为未生成。
- `public/inventory-summary-ui.js` 已按卡面显示来源批次，但部分操作要求打开原记录，追加指向 /pools；本轮改为详情内完成。
- 复用 `src/stock-adjust.mjs` 盘点调整、`src/gifts.mjs` 赠品、`src/bulk-finance.mjs` 未知成本补录、`src/cost-math.mjs` 精确分摊。
- 已知成本、原购入数量、日期及备注的统一批次更正接口需补齐，不能将现有仅补未知成本的接口改成无条件覆盖。

## 操作流程
首页详情 → 当前卡面/整组操作 → 内联填写 → 全量校验/影响预览 → 确认保存 → 原详情就地刷新。
校验失败回到原表单并保留输入；返回取消保留原详情的展开和滚动位置；响应不确定先查原请求结果，再安全重试。
新增购买追加真实批次；补成本修改原批次成本，不加数量；更正记录留存前后值/原因/时间；盘点差异单独记录调整。

## 数据约束
固定卡面编号、原始库存ID、批次ID及销售引用保持有效。不得重建同名首页项、虚构历史采购批次或覆盖历史轨迹。成本留空未知、0已知零成本。已售/已赠/自留关联先校验；涉及历史利润的更正必须预览影响后确认。保留整数分分摊、来源及审计。任何失败整批不写入，重试幂等。

## 实施和验收顺序
1. 最新代码及生产数据备份；追踪全部入库入口与记录展示。
2. 批次更正及影响预览、来源审计、账号隔离与重试测试。
3. 紧凑详情和内联操作，保留展开/滚动/表单状态。
4. 卡池入库可查批次；原批次补成本不改数量；多批次加权正确；调整和更正轨迹可查；关联数量不足拒绝；桌面/手机无大图与宽空输入框。
5. 页面验收通过后按本机GitHub发布流程上线，报告版本、数据核对及代码回退基线。

## 实现索引与边界
- `public/detail-operations.js`：紧凑内联操作、按账号草稿、原请求核查重试、展开位置保留；复用现有数量、FIFO、赠品和汇总。
- `src/batch-correction.mjs`：更正预览、原批次更新、整数分成本重分摊、销售/赠品/有明确来源的自留转移同步和更正审计。
- 新批次记录入口来源与保存时间；历史缺少时间的批次明确显示未记录，不补造历史。
- 更正转移记录的成本请从其来源批次进入；有盘亏或旧拆分且来源不明确时禁止自动重新分摊成本，日期/备注仍可更正。不得猜测旧数量去向。
- `tests/batch-correction.test.mjs`：原批次更正、未知与零成本、销售与赠品撤销守恒、自留来源链、重复请求、陈旧预览及非法输入。
